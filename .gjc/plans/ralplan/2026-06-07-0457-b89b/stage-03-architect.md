## Summary
Option A is architecturally sound for the approved LuminaQuant alpha-improvement spec: it keeps broad search in research lanes, freezes survivor candidates on train/validation evidence, and moves only strict-gate leaf survivors into Strategy/registry plus artifact-manifest composition. Architecture is non-blocking but remains WATCH because the risky surfaces are the existing large monthly-WF runner and alias-heavy artifact portfolio mode; the fail-closed schema and freeze gates must be treated as mandatory.

## Analysis
- Spec compliance: The spec requires broad existing-strategy and new-alpha smoke, Strategy classes for surviving leaf alphas, artifact portfolio manifests, MDD <=30%, no liquidation, strict two-tier benchmarks, train/validation-only portfolio sizing, fresh-forward evidence, and no real-money execution (`.gjc/specs/deep-interview-alpha-strategy-improvement.md:35-38`, `:63-73`, `:87-92`). The planner mirrors those requirements in its summary, principles, phases, and acceptance criteria (`stage-02-planner.md:7`, `:13-17`, `:67`, `:76`, `:82`, `:91-97`, `:136-138`).
- Benchmark grounding: The current reports support the planner constants: risk-trimmed shadow is 64.42% comp / 18.46% MDD / return-MDD 3.49, clean baseline is 34.39% comp / 27.69% MDD, and real-money remains blocked (`current_top_models_20260618.md:18-19`, `:50-53`). The portfolio report also warns that current rows are highly correlated and that `shadow70_clean30_v1` is paper/shadow-only with a 2.25x gross cap and stale/OOS fail-closed requirements (`top_strategy_correlation_portfolio_20260618.md:34`, `:50-62`, `:87-89`).
- Fit with existing architecture: `run_alpha_zoo_clean_new_alpha_discovery.py` is already a separate clean lane that declares no post-OOS meta-selector or lagged-shadow inputs, guards selection against locked-OOS use, attaches locked-OOS as report-only fields, records hashes, and sets `ready_for_real=false` / `clean_promotion_eligible=false` for current discovery artifacts (`scripts/research/run_alpha_zoo_clean_new_alpha_discovery.py:1-8`, `:486-549`, `:580-596`, `:1042-1054`, `:4384-4416`). Reusing it is better than duplicating metric logic in a greenfield engine.
- Monthly WF boundary: The existing monthly runner already contains non-leaf/hybrid exclusion concepts and clean leaf filters (`run_alpha_zoo_69_asset_monthly_refit_walkforward.py:804-856`, `:6979-7078`), so the frozen-survivor wrapper is credible. WATCH remains because the same file also hosts TradFi switches, lagged shadow routers, selectors, and portfolio-like rows; implementation must keep new clean manifests insulated from those mixed historical research lanes.
- Strategy/registry surface: `registry.py` supports curated strategies and plugin discovery, and has research/live tier hints (`src/lumina_quant/strategies/registry.py:156-201`, `:292-399`). The planner is correct to implement only strict-gate leaf survivors as Strategy classes, but implementation must not rely on the registry default tier for newly discovered plugins; every new survivor needs explicit non-real tiering until paper/shadow/fresh-forward gates pass.
- Artifact portfolio surface: `artifact_portfolio_mode.py` currently resolves alias/path-backed components, merges weights, instantiates child strategies, and scales child signal metadata (`src/lumina_quant/strategies/artifact_portfolio_mode.py:159-246`, `:699-763`, `:1729-1980`, `:2010-2164`). The manifest-driven additions are architecturally appropriate, but this is the highest-risk change because current code is alias-oriented rather than a self-validating frozen manifest with freshness, source hash, gross cap, and OOS-contamination enforcement.

### Strongest steelman antithesis
The strongest argument against Option A is that it extends exactly the two most historically accreted surfaces: the 8k-line monthly WF runner and the 2k-line artifact portfolio mode. A greenfield engine could make contamination states, freeze hashes, data sufficiency, and manifest replay invariants first-class from day one; Option A may accidentally inherit post-OOS labels, lagged shadow conventions, or alias-only portfolio behavior and create false confidence under a clean-looking report. This argument matters because deliberate-mode alpha research can be invalidated by one hidden tie-break or correlation input.

Synthesis: keep Option A, but execute it as a hard-gated extension, not a convenience patch. If clean discovery and existing-strategy smoke cannot be isolated behind explicit schema, freeze, and lineage fields, or if manifest replay cannot fail closed without current alias shortcuts, the invalidation clauses should force a wrapper split or greenfield component for that slice.

### Explicit principle-violation check
- Locked-OOS contamination: No planner violation found. The planner says locked-OOS is report/gate only and never selection, objective, tie-break, correlation, or portfolio sizing input; existing discovery code has matching `uses_locked_oos_for_*` guards and report-only fields. Required implementation check: locked-OOS perturbation must leave survivor selection, weights, and freeze hash unchanged.
- Weak-data TradFi promotion: No planner violation found, but WATCH. The planner correctly forces weak-data TradFi to shadow/research-only. Existing monthly TradFi candidates include paper/shadow rows with broker-calendar caveats, so implementation must add explicit data-sufficiency and weak-data labels before any clean/paper promotion.
- Strategy-vs-manifest boundary: No planner violation found. The planner keeps leaf alpha logic in Strategy classes/registry and risk/allocation in artifact manifests. Required implementation check: do not create a fake Strategy class that only replays a portfolio row; manifest composition must reference real child signal emitters and fail to cash when children are unavailable or stale.
- Portfolio optimization leakage: No planner violation found. The planner specifies train/validation-only return-MDD/Calmar optimization with correlation penalty and treats `shadow70_clean30_v1` as a benchmark/control, not automatic final. Required implementation check: locked-OOS and current-fold OOS must not be correlation, tie-break, or top-level sizing inputs.
- Fail-closed behavior: No planner violation found. The planner requires cash/no-promotion on missing/stale artifacts, weak data, liquidation, MDD breach, benchmark failure, unreconciled children, current-fold OOS, or gross-cap breach. Required implementation check: manifest resolution should prefer explicit cash/no-promotion reports over silent best-effort fallbacks.

## Root Cause
The fundamental architectural tension is maximizing alpha search breadth while preserving evidentiary trust. The codebase already has useful clean-selection primitives, but clean, shadow, TradFi, lagged, and portfolio concerns coexist in shared research/runtime surfaces; the plan must therefore make freeze hashes, provenance, data sufficiency, and fail-closed manifest validation the primary contracts rather than relying on naming conventions.

## Findings
1. Severity: LOW — `src/lumina_quant/strategies/registry.py:292-399`. Impact: plugin-discovered strategies without explicit tier hints can fall back to `live_default`, which is a poor default for newly discovered research leaves even though real-money remains excluded. Fix: implementation should add explicit tier metadata/hints or tests proving new survivor strategies are excluded from live/default maps until the promotion gate says otherwise.
2. Severity: LOW — `src/lumina_quant/strategies/artifact_portfolio_mode.py:1729-1980` and `:2010-2164`. Impact: current portfolio mode resolution is alias/path-backed and scales child signals, but does not itself prove frozen manifest freshness, source-artifact reconciliation, top-level gross cap, or no-current-fold-OOS provenance. Fix: treat Phase 6 manifest schema, deterministic replay, gross cap, stale/missing fail-closed behavior, and source hash checks as required acceptance, with compatibility tests around existing aliases.
3. Severity: LOW — `scripts/research/run_alpha_zoo_69_asset_monthly_refit_walkforward.py:804-856`, `:2319-2473`, `:6979-7078`. Impact: the monthly runner contains clean leaf filters and TradFi controls, but also many selector/portfolio/non-leaf families; an implementation that directly extends the runner without a frozen-survivor wrapper could blur clean promotion boundaries. Fix: prefer the frozen manifest interface when adding existing-strategy smoke and full-WF promotion, and keep no-nested/no-post-OOS material tests mandatory.

## Recommendations
1. Route to Critic; architecture is not blocking.
2. Preserve Option A with WATCH constraints: schema/freeze contract first, broad smoke second, full WF only for frozen survivors, Strategy implementation only for strict-gate leaves, manifest composition only from reconciled components.
3. Make the manifest schema fail closed by construction: source artifact path+sha, generated time, child readiness, selection inputs, fresh/stale threshold, gross cap, per-leaf netting, correlation inputs, and OOS-contamination flags should all be validated before runtime composition.
4. Require explicit tiering for every new Strategy/registry survivor and tests that `ready_for_real=false` / `real_money_execution=false` remain true until separate approval and fresh-forward evidence.
5. Keep no-promotion as an acceptable final state; do not weaken benchmarks or MDD/liquidation gates to force an improvement.
